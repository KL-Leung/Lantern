# 青灯

青灯是一个基于 [chat-demo](https://github.com/deepseek-ai/chat-demo) 二次开发的静态角色卡文游工作台。当前目录是构建后的可发布版本：没有应用后端，浏览器直接请求配置的 API；对话、角色卡、世界书和模板都保存在本地浏览器。

> 原项目：<https://github.com/deepseek-ai/chat-demo>（MIT License）
> 本项目在原项目基础上增加角色卡、世界书、System Prompt 模板、归档 v4 与 WebDAV 同步，整体按 **PolyForm Noncommercial 1.0.0** 分发，禁止商业使用。原始 MIT 声明保留在 `LICENSE` 中。

## 快速开始

1. 打开页面后，若还没有可用配置，会直接打开 **设置 → 模型**。
2. 先选供应商（DeepSeek / OpenAI / Claude / Gemini / Azure / Moonshot / 智谱 / 通义 / Ollama 等），再填 API Key，点「获取模型列表」从下拉选择模型；取不到时可手动填写模型名。本地供应商（Ollama、LM Studio）无需 Key。
3. 左侧已有 9 个示例角色（古风、科幻、校园魔法、赛博朋克、仙侠、西幻、末日、旁白等），选一个直接开聊，也可在设置 → 角色里新建或导入。
4. 想要多人对话，点侧栏「**新建群聊**」：选 2–6 个角色、选发言顺序，创建后进入群聊。
5. 可选：在 **设置 → 世界书** 创建关键词/常驻条目，并在角色编辑器里绑定。
6. 想让角色「一定记住」某件事，可在助手消息上点「设为必记」，或在会话「记忆」面板手写一条。

设置侧栏分「基础」与「高级」两组，不做折叠，按使用频率排序：

- **基础**：模型、角色、使用说明、通用、世界书、人设、数据管理
- **高级**：记忆、Prompt 块、资料库、正则、HTTP 工具、同步

用静态服务器托管本目录，或部署到 GitHub Pages。

直接双击 `index.html` 也能尝试使用，但 `file://` 下的 IndexedDB、麦克风和跨域行为因浏览器而异；正式使用建议用 HTTPS 或 localhost。

## 已实现

### 角色与文游

- 首次启动内置 **9 个示例角色**，覆盖古风、科幻、校园魔法、赛博朋克、仙侠、西幻、末日与纯旁白；可直接开聊，也可编辑或删除。新增示例只补缺的，不会覆盖你改过或删掉的角色。
- 未配置可用模型时，欢迎页显示提示条，点击即打开设置 → 模型。

- 角色卡新建、编辑、删除；名字、**性别**、emoji/图片头像、设定、性格、场景、开场白、备用开场白、示例对话、作者指令、Post-History、角色笔记/Depth、标签；新会话可「换一个开场白」切换候选。
- 性别属性可选 男 / 女 / 男同 / 女同 / 双性 / 无性 / 硅基，**仅作资料展示不自动进 prompt**；需要影响对话时请在角色设定或设定事实里写明。
- 角色设定事实：在角色编辑页按行填写，跨会话生效，每轮注入，不随时间衰减。
- 头像上传会自动缩放到 256px WebP；聊天页标题旁显示当前角色/发言者头像。
- AI 生成角色头像：通过 OpenAI 兼容图像接口生成 1024×1024 头像并保存到 assets。
- 聊天内场景图：会话标题旁「生图」，可选方形/横图/竖图与 natural/vivid 风格；生成后插入一轮用户提示 + 助手图片消息；图片存 assets 并随归档导出。
- 窄屏会话头把生图、注释、记忆、状态、压缩上下文收进「更多」菜单，功能不再丢失。
- 新对话选择角色；会话绑定角色、显示角色名标题；开场白作为第一条消息展示并持久化。
- 角色 Prompt 进入 system：角色字段、示例对话、开场白、作者指令；`{{char}}` / `{{user}}` 占位符替换。
- 世界书：关键词/常驻条目、次级关键词、大小写/全词/正则匹配、概率、启用开关、顺序；条目可放系统提示或按深度/角色插入聊天；包含组同组只激活一条（按组权重）；递归激活（最多 3 层）；Sticky/Cooldown/Delay 时序；扫描最近 N 条消息；字符预算；角色绑定；命中测试面板。
- 资料库 RAG：全局/角色/聊天作用域文档、切块、关键词/embedding 混合检索、最低分数阈值；embedding 按文档块持久化缓存，文本/模型变化时重建；相关片段注入记忆区。文档仅存本地 IndexedDB，不随归档导出。
- System Prompt 模板：角色模式 / 默认助手两套全局模板；角色可填写自己的模板覆盖全局模板，支持变量、预览、恢复默认。默认模板可直接使用，编辑入口在「设置 → Prompt 块」页内展开。
- 用户人设：多个人设、头像/名字/**性别**/描述，选择当前身份；`{{user_name}}` / `{{user_description}}` 进入 Prompt；随归档 v4 同步。
- 角色卡 JSON/PNG/charx 导入导出：JSON 兼容 SillyTavern V1/V2 字段；PNG 读取 `chara`/`ccv3` 并保留原图为头像，导出用头像图作 PNG 壳；charx 读取 `character.json`；内嵌 `character_book` 转为绑定世界书。性别写入自定义字段 `chat_demo_gender`，SillyTavern 原生卡片不受影响。
- 世界书 JSON 导入/导出：支持本项目格式与 SillyTavern standalone；导入时按 `bound_character_ids` 恢复已有角色绑定。
- AI 生成角色卡：用一句话描述角色，模型生成并保存角色卡。

### 对话

- 多会话、重命名、删除；默认助手会话自动生成标题，角色会话使用角色名；消息分支、版本切换、编辑提问、重新生成、继续生成。
- 流式回答、深度思考、智能搜索、链接阅读、来源引用；停止生成。
- 附件上传、粘贴、拖拽；语音输入、回复朗读。
- Markdown、代码高亮、KaTeX 公式、Mermaid 图表。
- 单条回复的 Token 用量：默认只显示「用量 N token」，**点击展开**明细（模型、缓存命中率、未命中输入、缓存写入、缓存读取、输出、输入合计），点外部或按 Esc 收起。数字用 k/m 缩写避免过长。<br>压缩上下文时同样记录并显示该次压缩消耗的 token。
- 剧情摘要与上下文压缩：手动压缩 + 自动阈值压缩；较早消息生成摘要，请求时用摘要替代旧历史，最近 12 条保留原文；摘要可编辑、删除、回查原文。会话标题旁「压缩上下文」。单条回复可翻译。
- **压缩分界标记**：每次压缩后在消息流对应位置留一条「已压缩 N 条上下文 · 时间」的分隔线，点开可看摘要正文与该次压缩的 token 消耗；随会话持久保存，刷新后仍在。
- **长消息折叠**：正文超过 320px 自动折叠到 220px，底部渐隐提示；点「展开全文」向下铺开，且**不会把页面甩到底部**。短文不显示按钮。
- 分层记忆：角色设定事实（跨会话、不衰减）→ 会话必记（按提及衰减）→ 剧情摘要 → 可检索事实 → 原文，按此顺序注入 `{{memory}}`。
- 会话必记：可手写或从消息「设为必记」，每轮注入；强度按提及变化（未提及 -3 / 提及 +5），分四档呈现：完整、记忆模糊、只记得关键词、已遗忘；遗忘后保留条目并可一键唤醒。
- 角色设定事实：在角色编辑页按行填写，跨会话生效，每轮注入，不随时间衰减。
- 事实记忆：模型提取或手动添加，支持编辑与删除；压缩上下文成功后自动提取一次，也可在记忆面板手动触发。
- **群聊**（侧栏「新建群聊」）：最多 6 个参与者，**发言顺序四选一**——
  - **手动指定**（默认）：发消息后不自动回复，点输入区上方的角色头像让它发言
  - **自然顺序**：优先回应被提到的人，否则按「健谈程度」概率随机
  - **列表顺序**：按参与者列表顺序轮换
  - **智能判断**：由模型根据上下文判断谁该发言（每轮多消耗一次调用，失败自动降级到自然顺序）

  另外支持：点角色即可让它插话（任何策略下可用）、静音成员、角色卡 Join（合并所有参与者信息）/ Swap（只放当前发言者）模式。群聊会话在侧栏带人数徽标，与单聊区分。
- **群聊点名**：每个角色的 system 里都会列出**全部在场角色**（含自己标注「（你）」与用户），并附群聊规则，因此角色可以直接呼唤对方名字；被点到的人在「自然顺序」下会被优先选中接话。
- Author's Note：聊天级注释，可设置深度、角色和每 N 轮插入，用于格式/语气/临时设定。
- Prompt 块：设置中按顺序/角色/In-Chat Depth/生成类型拼装自定义内容；相对 system 块并入系统提示，user/assistant 块放历史前。
- Prompt 预设：导出/导入自有模板 + 块 + 采样参数；可导入 SillyTavern Chat Completion 预设，映射 `prompts[]`/`prompt_order[]` 为 Prompt 块并同步 temperature/top_p/top_k/max_tokens（marker 跳过，main/jailbreak 停用保留）。请求时会展开 `{{char}}`/`{{user}}`/`{{persona}}`，其他 ST 宏原样保留。
- 状态栏：会话级键值状态，随请求注入 `{{state}}`，并随归档保存。
- 上下文预算：设置上下文窗口；会话标题显示服务端实际返回的 token 用量（接口不返回 `usage` 时不显示）；达到 80% 时请求前自动压缩较早消息；服务端返回上下文超限时再压缩并重试一次。
- 本地记忆检索：关键词/embedding 混合检索注入 `{{memory}}`；可选开启 `recall_memory`，让模型按需取回当前分支原文片段。
- 事实抽取：会话「记忆」弹窗可提取长期事实，压缩上下文成功后也会自动提取；保存后参与本地检索。
- 展示正则：设置 → 正则维护 find/replace 规则，只影响助手回复渲染，不改写原消息。
- **会话侧栏**：按标题搜索；自定义分组（新建/改名/删除，空分组也显示，可把会话移入移出）；群聊带人数徽标。
- 模型配置：支持多套命名配置（名称必填，可切换/新建/删除）；每套记录供应商、协议、地址、模型、Key、生图模型。默认只显示配置列表与摘要，点「查看完整设置」才展开表单；生图、向量、生成参数、上下文窗口收进高级折叠项。
- 供应商预设：DeepSeek、OpenAI、Anthropic Claude、Google Gemini、Azure OpenAI、Moonshot、智谱 GLM、通义千问、Ollama（本地）、LM Studio（本地）、自定义。选中预设会自动填好协议与地址，只需填 Key。
- 五种协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini 原生 API、Azure OpenAI（部署名作模型名 + `api-version`）。
- **图片输入**：五种协议全部支持。Anthropic 走 Files API（`file_id`），其余四种走 base64 内联（`image_url` / `input_image` / `inlineData`）。图片上传失败会自动回退内联，不会卡住发送。
- 获取模型列表：按协议调 `GET /models`（Azure 走 `/openai/deployments`，Gemini 走原生 `/v1beta/models`）；取不到自动切手动填写。Key 校验只在 HTTP 401 时拦截，供应商不提供 `/models` 也不会阻止保存。
- **生成参数**：温度 / Top P / Top K / 最大长度（上限 128k）都改为**滑块 + 数值框 + 范围与推荐值**，滑块轨道上用淡色标出推荐区间，并附一句说明与常用预设一键套用；留空表示使用服务端默认。
- 本地供应商免 Key：Ollama、LM Studio 无需填写 Key，也不会被首启拦截。
- 生图与 Embedding 可单独配置供应商：各自填接口地址与 Key；留空则复用对话配置。
- HTTP 工具：设置 → HTTP 工具定义 GET/POST 接口，支持 URL/body 的 `{query}` 占位和自定义 headers；可要求模型调用前逐次确认（Anthropic/OpenAI 函数工具）。

### 数据与同步

- 会话、附件、角色卡、世界书、模板保存在 IndexedDB；设置与 API Key保存在 localStorage。
- 归档 v4 导出/导入：会话、上下文摘要、必记、角色卡（含设定事实）、世界书、人设、提示词模板、角色绑定、开场白、图片头像资源、本地图片。
- v3 旧归档仍可导入，只恢复会话并保留现有角色数据。
- WebDAV 手动上传/恢复完整备份；需要服务器允许 CORS。
- 删除所有对话只清空会话、附件和草稿，保留角色卡、世界书、模板、API Key 和设置。
- 简体中文/英文、浅色/深色主题、移动端布局、设置内置使用说明。

## 尚未实现

以下按能力列出当前边界，已支持的部分一并写明，避免误判。

- **聊天内生图增强**：支持尺寸与 natural/vivid 风格；不支持多图、局部重绘或图片编辑。
- **群聊**：四种发言顺序、点名、静音、手动插话、Join/Swap 角色卡模式已支持；**每轮只产生一条 assistant 消息**（不并发多人，也不自动连续生成），需要多人接话时点角色头像。`multiSpeak`（一次回复多人分段）与 `autoChain`（自动接龙）已移除。
- **聊天页角色头部**：标题旁已显示当前角色/发言者头像；无角色名的旁白消息使用弱化斜体样式。
- **自动记忆增强**：手动/自动压缩、角色设定事实、会话必记与提及衰减、关键词/embedding 混合检索、`recall_memory` 原文回查、事实提取与编辑已支持；结构化时间线（主体-谓词-客体）未做。
- **必记衰减结算**：只在压缩上下文时计算，两次压缩之间的新增必记不衰减；强度归零不自动删除，只标记「已遗忘」。当前「提及判定」要求命中内容词的 60%，实际偏严——不常被原样提及的必记会较快淡忘。
- **群聊调度成本**：「智能判断」策略每轮多一次模型调用；其余三种策略为本地算法，不额外消耗。
- **HTTP 工具边界**：Anthropic/OpenAI 函数工具已支持；逐次确认可配置；POST body 支持 JSON 模板并自动转义 `{query}`，非 JSON 模板按纯文本替换。
- **多套命名模板**：全局两张 + 角色级覆盖已支持；模板可通过「Prompt 预设」整体导出/导入；模板命名与多套并存未实现。
- **模型高级能力**：多套命名配置、供应商预设、获取模型列表、五种协议、五种协议的图片输入已支持；OpenAI 函数工具调用与 `reasoning_content` 思考流已支持；OpenAI Responses 推理内容（`reasoning_text` / `reasoning_summary_text`）已支持。Gemini 函数调用未接入；多模态（音频/视频）附件、服务端搜索、自动标题和任务级模型选择仍未实现。
- **归档互通**：本项目导出的是 `export_format_version: 4`，官方 chat-demo 只接受 3，因此**导出到官方会因版本号被拒**；官方 v3 归档可以导入本项目。尚未提供「导出为官方兼容格式」选项。
- **charx 资源**：`character.json` + `card.png` + 头像已支持；charx 内的其他资源/扩展未处理。
- **社区/账号/云同步后端**：没有角色广场、评论、账号体系或官方云同步；同步只走用户自己的 WebDAV。

## 已知限制

- 纯静态应用，没有后端代理；API 服务必须允许浏览器跨域。
- WebDAV 同步是手动覆盖式，服务器必须允许 CORS；Nextcloud 需要配置 `cors.allowed-domains`，部分托管 WebDAV 可能不支持。
- API Key 存在 localStorage，不要在公共电脑上保存。
- 数据按浏览器和 origin 隔离；换浏览器、清空站点数据或更换域名会读不到旧数据，请定期导出归档。
- 长对话受模型上下文窗口限制；自动压缩依赖接口返回的 token 用量，接口不返回 `usage` 时不会触发，需要手动压缩。
- **必记会淡忘**：强度只在压缩上下文时结算，按「未提及 -3 / 提及 +5」变化，且「提及」要求命中内容词的 60%。实测每 3 轮才提一次仍会缓慢下滑，每 4 轮以上必然归零。重要设定建议写进「角色设定事实」——那部分不衰减。
- 群聊每轮只产生一条回复，不会自动连续生成；需要多人接话时点角色头像。
- 导入 v4 会替换本地角色卡、世界书、模板、人设和头像资源；导入 v3 不会。
- 构建产物只包含静态文件，不包含任何账号或 API Key。

## 开发

源码仓库在 [chat-demo](https://github.com/deepseek-ai/chat-demo) 的基础上开发，使用 React 18、rspack、zustand、IndexedDB、fflate、Prism、KaTeX、Mermaid。

```sh
pnpm install
pnpm dev      # http://localhost:8090
pnpm build    # 输出到 dist/
pnpm type
pnpm lint
```

构建配置默认连接 `https://api.deepseek.com`；可通过 `createConfig({ apiOrigin })` 修改。

### 发布到 GitHub Pages

线上仓库只保留构建产物，源码不进远端：

```sh
pnpm release          # 构建 + 只推送 dist 到 origin/main
pnpm release:check    # 只校验产物，不推送
```

脚本 `scripts/release.mjs` 会依次：构建 → 同步 `README.release.md` 到 `dist/README.md` → 校验 `index.html` 与资源路径 → 用临时 worktree 生成孤立提交 → 强制推送。

可用参数：

| 参数 | 说明 |
| --- | --- |
| `--no-build` | 跳过构建，直接发布现有 `dist` |
| `--branch <name>` | 推到其他分支（默认 `main`） |
| `--dry-run` | 只检查，不推送 |
| `--message <text>` | 自定义提交信息 |
| `--allow-dirty` | 跳过未提交改动的提醒 |

强制推送会整体替换目标分支历史，这是「只发布产物」的预期行为。临时 worktree 与本地分支在结束时自动清理。

### 访问统计（可选）

GitHub Pages 不提供访问量统计。如需统计，可接入 **Cloudflare Web Analytics**（免费、无 cookie、不跨站追踪）：

1. 在 Cloudflare 控制台 → **Web Analytics** → **Add a site**，hostname 填 `kl-leung.github.io`。
2. 在 **Manage site** 复制 JS 片段，取出其中的 `token`。
3. 二选一提供 token：
   - 环境变量：`$env:CF_BEACON_TOKEN = "你的token"`
   - 或写入项目根目录的 `.cf-beacon` 文件（已在 `.gitignore` 中，不会进仓库）
4. `pnpm release` 构建时会自动注入 beacon。

不配置 token 时产物**不包含任何统计脚本**，本地开发和自建部署都不会产生上报。本应用无 URL 路由，不需要 Cloudflare 的 `spa: true` 选项。

说明：接入统计意味着向 Cloudflare 发送访问记录（IP、UA、页面路径），启用前请自行评估是否需要在使用说明中告知用户。
